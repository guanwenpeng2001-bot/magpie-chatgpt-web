# ChatGPT Web for magpie

Development snapshot: provider registration, browser sign-in, session renewal, model discovery and text turns. Replies stream in append batches as the site writes them; this is not token-level streaming. Prompt-level tool emulation is implemented and tested offline. Its live compliance matrix is PENDING, so every model advertises `toolcall: false` and ships as text-only. A later commit may enable an individual model only after its pre-committed matrix passes.

Requires Node.js 20 or later on PATH and installed Google Chrome. Install the local repository with:

```sh
magpie plugin add /absolute/path/to/magpie-chatgpt-web
magpie plugin login chatgpt-web
```

Adding a plugin restarts magpie's plugin host. Select **ChatGPT account (browser sign-in)**. A normal Chrome window opens on chatgpt.com using a separate plugin-owned profile. Sign in normally; no cookie copying or token pasting is needed. The window closes after the session is verified. Chrome is spawned without automation, headless or no-sandbox flags and attached over CDP.

Magpie stores the session cookie and derived access token in its own credential store. Login verifies the session inside the signed-in browser and captures rotated HttpOnly session cookies. Renewal starts 24 hours before token expiry and first uses the stored cookie without opening Chrome; a positively identified interstitial routes that read through the plugin-owned browser. Clearance cookies stay in the browser that earned them. An expired cookie triggers magpie's sign-in-again affordance. Each sign-in uses a fresh profile slot under `~/.config/magpie/chatgpt-web-profile/`; restored pages are reset to a blank page before use without deleting cookies. A failed reset produces an error; signing in again allocates another slot. Old profile cleanup is not yet automated.

Browser state is a sensitive login artifact; never share the profile; use a trusted workstation. Web-session automation is unofficial, can break when the site changes, and may risk account restrictions. Use only an account you are authorized to access. Challenges and rate limits are not bypassed or retried automatically.

The model catalogue is fetched per account and cached in memory for 60 seconds. Successful Node reads do not launch a browser. A confirmed challenge triggers one browser read; if that also fails, the catalogue reports an error rather than an empty or shortened list. A challenge reports “ChatGPT asked to verify you are human. Complete verification in the open browser, then retry the chat.” It does not mark the session expired. An unmarked 403 remains a credential rejection and blocks further account work. Catalogue inclusion does not prove a model is selectable or can generate; INC-6 reconciles it against the picker and generation evidence. Duplicate mini-model titles include their slug. Advertised limits (200,000 context; 34,834 output) are planning values, not verified subscription or generation guarantees.

No attachment or image input, reasoning controls or traces, native tool API, web search/canvas/image tools, or quota display is provided. The emulation machinery accepts explicitly supplied client tool definitions for verification, but the model catalogue does not advertise tool support. It asks for nonce-delimited JSON in ordinary model text, validates it, and renders synthetic `tool_use` blocks; it never executes a tool. Each argument object is rendered in one `input_json_delta`, not a native per-token argument stream. Text outside calls continues to stream incrementally. Tool histories preserve call IDs, results and error flags as text and replay the full history in a fresh temporary chat. Text-only requests keep normal binding: the host delivers its session id through `chat.headers`; a caller-supplied `conversation_id` takes priority, otherwise its SHA-256 identifies the local binding. Bindings expire after 30 idle minutes; lost pages rebuild from the full supplied history.

Tool definitions are validated before a turn starts. The bounded schema subset supports boolean child schemas, `type` (including unions), `const`, `enum`, `properties`, `required`, `additionalProperties`, `items`, `uniqueItems`, `allOf`, `anyOf`, `oneOf`, `not`, local `$ref`, `$defs`, `definitions`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength`, `minProperties`, `maxProperties`, `minItems`, and `maxItems`. `title`, `description`, `default`, `examples`, and `$comment` are annotations only. Every other keyword is rejected, including `$schema`, `pattern`, `format`, remote references, conditionals and tuple schemas. Preflight is bounded to 10,000 nodes and depth 32; argument validation to 100,000 operations and depth 32; a call is limited to 1 MiB of JSON and a request to 128 tools.

Invalid definitions or an undefined forced tool produce HTTP 400 before dispatch. Unknown tools, malformed JSON or delimiters, schema mismatch, a tool-choice violation, disabled parallel calls, incomplete calls, and a missing required call produce distinct fixed errors rather than successful prose. For example: "ChatGPT returned malformed tool-call JSON.", "ChatGPT tool arguments do not match the input schema.", and "ChatGPT did not produce the required tool call." Streaming failures end with an error event and no successful `message_stop`; nonstreaming failures return an error response. The emulation port and test cases are attributed in `THIRD_PARTY_NOTICES`.

Turns currently open ordinary visible Chrome, the launch shape supported by the live spike; working headless generation remains unproven. New pages request `?temporary-chat=true`; a redirect that loses that flag fails before submission. Cancelling closes the active page and drops its binding, while retaining the browser session for the next send. Local discard never deletes a remote conversation.

Network collection preserves answer text and Markdown. If cloning is unavailable before any answer is forwarded, DOM prefix snapshots provide incremental plain text with reduced formatting fidelity. A reader failure after collection starts, incomplete stream, hidden reply, empty reply or changed vocabulary produces an explicit error, never a fabricated completed answer. Rate limits keep the account cooldown even if their dialog is dismissed. Interactive verification requires manual action in the sign-in browser; no challenge is solved or retried automatically. Before the first answer batch, the request remains pending; no invented progress text is inserted. Usage counts are character-based estimates. Expiry of the backend's local request time budget reports HTTP 504 with “This request exceeded its local time budget and was stopped before any confirmed result.” This is distinct from an upstream rejection or an account rate limit. A read has a default 20-second Node budget; a positively challenged read receives one independent browser fallback budget of another 20 seconds, for an active-read bound of approximately 40 seconds, excluding time queued for the account guard and subject to earlier caller cancellation. Reads serialize per account, so queued reads also wait for that occupancy and guard pacing. A typed expiry or cooldown discovered before slow browser cleanup is recorded by the guard immediately, even if the caller subsequently receives a local-budget 504.
